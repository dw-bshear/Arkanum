# Arkanum 1.0.0

## Scope and immutable history

This source implements the authorized transition from the legacy calendar version `2026.1.2` to feature-based SemVer `1.0.0`, alongside the design-review changes. Versions advance by delivered compatibility/features/fixes, never by year. Application/assembly metadata, Windows CLI/GUI defaults, Linux CLI defaults, full/update packaging defaults and current operator examples now use `1.0.0`.

This file does not claim publication, tagging, final package integrity verification, or deployment has already occurred. The release operator builds all four assets from the final source commit and verifies checksums/payloads before publishing a new immutable `v1.0.0` release. All older release tags, notes, assets, checksums and provenance remain unchanged. The existing **2026.1.2 Security Evidence** tooling/package continues to assess only that exact historical release; no new security assessment or approval is implied.

## Website changes

- Bundled Adobe Source Sans 3 replaces the previous system-dependent font stack. Font assets and their SIL Open Font License ship with the offline application; no CDN is required. Existing font sizes, weights, spacing and layout rules are retained.
- Removed the explanatory **Settings layout** card without removing permission information, settings tabs, forms or handlers.

## Upgrade behavior

- Full and update installers recognize exactly `2026.1.2` as the supported legacy upgrade source. The numeric calendar reset is not mistaken for a downgrade.
- New-family major/minor/patch and prerelease identifiers use SemVer precedence; build metadata does not affect ordering. Genuine downgrades, malformed/unknown families, missing/corrupt install-state and different-version repair fail before application/service mutation.
- Equal-precedence reinstall/repair preserves state and takes a backup. An explicit repair must use the same version; choose upgrade for a newer target.
- Both GUI entry points delegate to their CLI, so the same checks apply. A full package's install/restore action cannot bypass an existing-install version decision.
- Existing Recovery Keys and runtime database connection files are reused; the default upgrade does not rewrite their contents. Existing appsettings and web.config are preserved over package defaults. Linux retains its systemd environment/service unit; Windows retains runtime configuration, existing IIS bindings and app-pool identity. Use the actual existing deployment paths, identity and health endpoint when invoking an upgrade.
- Both tracks run independent database schema/permission/key-sentinel preflight before app replacement. Linux now uses the shipped `--database-setup preflight` helper for upgrade **and repair**, rather than the obsolete migration-history SQL check. A product version change does not change schema version/migration state or initialize a database.
- Linux stops before replacement if app/config backup fails and backs up its service unit. Public `Alive` responses are accepted as liveness only, not proof of SQL/key readiness.

See `versioning.md` for the exact supported family boundary, action matrix, rollback procedure and native constraints. SQL backup is an independent DBA responsibility; retain the matching key and pre-upgrade app/config/state/binding backups. There is no installer downgrade override; rollback restores a matching backup under operator control.

## Package surfaces

```text
Arkanum-1.0.0-full-windows-x64.zip
Arkanum-1.0.0-update-windows-x64.zip
Arkanum-1.0.0-full-linux-x64.tar.gz
Arkanum-1.0.0-update-linux-x64.tar.gz
```

Each archive has its own SHA-256 sidecar and `package-manifest.json`; update manifests declare preserved site state. Both Windows assets retain the real pinned SHA512-validated Microsoft .NET 10 Hosting Bundle requirement. Runtime patch/security ownership remains with the operator.

Native DEB staging uses epoch **`1:1.0.0`** with product version `1.0.0`, outside the live `/opt/arkanum` destination, and carries a version manifest plus SQL installer inputs. Native prereleases/build metadata are rejected (use TAR). Direct upgrade from an old native DEB is rejected before unpack because legacy ownership of live `/opt/arkanum` files requires a separate migration plan. MSI was incomplete staging, not a supported install/update path; its script now always emits explicit staging instructions rather than attempting an unverified calendar-reset `MajorUpgrade`.
