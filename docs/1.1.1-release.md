# Arkanum 1.1.1

## Security fix

The browser password generator now uses rejection sampling instead of modulo
reduction for character selection and Fisher–Yates shuffle indices. This removes
the bias identified by CodeQL alerts #5–#7 while retaining cryptographic
randomness, the existing alphabet, 24-character length and required character
classes. No existing saved password is changed automatically. The findings do
not by themselves demonstrate compromise of any stored credential.

Four other CodeQL alerts were reviewed in the bundled jQuery/Validation code;
the recommended dispositions and supporting call paths are documented in
`codeql-triage-2026-10-28.md`. Vendor files are unchanged. A recommended false
positive is not a claim that GitHub dismissal has already occurred.

## Upgrade

Use the 1.1.1 **update** archive for an existing installation and the **full**
archive for first installation, isolated side-by-side review or supported
restore. Back up the application/configuration and database, retain the matching
Recovery Key, run preflight, and follow the regular platform installer workflow.
This patch adds no schema changes relative to 1.1.0. Upgrades from versions older
than 1.1.0 must still satisfy the credential-history schema/permission
prerequisites in `1.1.0-release.md`; version acceptance does not bypass them.

Updating GitHub source does not update an installed server. Install the new
package and refresh open browser sessions so the repaired script is loaded.

## Verification and boundaries

- Four Node password-generator regression tests pass, including rejection and
  equal accepted-index representation across all used bounds.
- 266 .NET regression tests and 72 Python tests pass with SDK 10.0.402.
- JavaScript syntax, shell syntax and diff checks pass.
- Development and shipped minified vendor validation probes pass for the
  exercised DOM-element paths; these are not complete browser security tests.

Release archives are built from the tagged source commit and carry a package
manifest, source provenance and checksum inventory. Windows includes the existing
pinned .NET 10.0.13 Hosting Bundle; Linux remains framework-dependent and requires
an approved ASP.NET Core 10 runtime. Historical releases remain unchanged.
Native Windows/IIS acceptance and a new comprehensive security assessment are
separate gates; neither is established by these targeted regression tests.
