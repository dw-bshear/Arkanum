# Arkanum 2026.0.6 feedback release notes

This prerelease packages the current feedback-window updates for Windows and Linux installer testing.

## Vault privacy and navigation UX

- Vault folders are collapsed by default when a user opens a vault.
- Each vault folder contains separate collapsed subtrees for:
  - `Credentials`
  - `Secure Notes`
- Entries are alphabetized inside each subtree.
- Entry titles are not shown until the user intentionally expands the folder and subtree.
- Reveal/copy actions preserve scroll position and reveal the selected value inline.
- Password/secure-note values remain masked as `******` until explicitly revealed.
- Visible audit wording was removed from the row UI, while backend audit events remain enabled.

## Credential row layout

Credentials now show:

```text
Title
Username
<username value>
Password
****** / revealed value
Reveal / Copy
Reset notification
```

The previous raw `LoginCredential` type label is no longer shown for credential rows.

## Secure note row layout

Secure Notes keep the `SecureNote` type label and reveal their protected value under a `SecureNote` label instead of `Password`.

Reset notification controls are available for secure notes as well, supporting software-key review/change reminders.

## Reset notification UX

- Reset notification date inputs are right-aligned after Reveal/Copy.
- Date selection auto-saves; the separate row-level Save button was removed.
- Setting or changing a reset notification date clears prior sent status.
- Reminder service behavior excludes global administrators from routine vault-member reminders.
- Reminder email content does not include secret values.

## Installer restore mode

Installers support `Restore from database backup` / `ACTION=restore`.

Restore mode requires an existing Arkanum Recovery Key by file or pasted value and does not generate a new key.

Windows GUI:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\installers\windows\Install-ArkanumGui.ps1
```

Choose:

```text
Restore from database backup
```

Then provide either:

```text
Recovery Key file
Paste Recovery Key
```

Linux CLI:

```bash
sudo env \
  ACTION=restore \
  ARKANUM_SQL_CONNECTION='Server=tcp:<host>,1433;Database=Arkanum;User Id=<user>;Password=<password>;Encrypt=True;TrustServerCertificate=False;' \
  ARKANUM_RESTORE_KEY_FILE='/path/to/master-key.txt' \
  installers/linux/install-arkanum.sh
```

If validation fails, restore mode reports:

```text
The provided Recovery Key does not match this database.
```

## CSV export

Vault pages include:

```text
Export vault CSV
```

Settings includes:

```text
Export all vaults
```

Exports are ZIP packages containing:

```text
manifest.json
credentials.csv.aes
```

The CSV payload is encrypted using the export passphrase with AES-256-CBC and PBKDF2-SHA256. Audit logs record that an export occurred without logging secret values.

PDF reports remain deferred for later feedback.
