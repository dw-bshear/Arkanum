# Arkanum 2026.1.2 source changes

## Windows Server 2022 installation

- Use the built-in elevated, 64-bit Windows PowerShell 5.1 host; no PowerShell 7 prerequisite.
- Replace incompatible modern .NET random-number API calls in setup with Framework-compatible cryptographic generation.
- Include a hash-verified Microsoft .NET 10 Hosting Bundle in Windows full and update packages; verify Microsoft Authenticode trust before installation.
- Add explicit consent for IIS feature preparation, Hosting Bundle installation, and possible shared-IIS service interruption. Support an offline Windows feature source and stop/resume for required restarts.
- Remove the Windows `sqlcmd` prerequisite in favor of an application-provided SQL provisioning/preflight command, with temporary environment-based credentials and redacted errors.
- Keep restored database/Recovery Key validation separate from public web liveness.
- Keep GUI command previews free of SQL credentials and pasted Recovery Keys.

See [Windows Server 2022 setup](windows-server-2022-setup.md) for the administrator workflow and remaining manual inputs.

## Runtime and packaging

Application/tests target .NET 10 LTS. SDK and Microsoft application dependencies are pinned; lockfiles include Windows/Linux x64 publish graphs. Linux native package metadata requires ASP.NET Core 10; Linux prerequisite installation remains operator-managed.

The .NET 10 migration also updates PBKDF2 calls without changing the encrypted export format, and explicitly pins the patched PKCS dependency to avoid an older vulnerable transitive version.

## Publication and validation boundary

This document describes the source changes, not a claim that a new GitHub release has been published. Do not replace immutable 2026.1.1 release assets. New release assets use 2026.1.2 and require their own approval/verification process.

Native Windows Server 2022 fresh-install, offline trust, restart/resume, shared-IIS impact, upgrade, repair, and restore acceptance must be recorded before production deployment. Cross-platform tests and package checks are not a substitute for native Windows installation evidence.
