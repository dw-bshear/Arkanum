# Arkanum 2026.0.4 feedback release notes

This prerelease is prepared for the next Windows x64 test window.

## Installer restore mode

Installers now expose `Restore from database backup` / `ACTION=restore`.

Restore mode requires an existing Arkanum Recovery Key by file or pasted value and does not generate a new key.

Windows GUI:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\installers\windows\Install-ArkanumGui.ps1
```

Choose:

```text
Restore from database backup
```

Then provide either:

```text
Recovery Key file
Paste Recovery Key
```

Linux CLI:

```bash
sudo env \
  ACTION=restore \
  ARKANUM_SQL_CONNECTION='Server=tcp:<host>,1433;Database=Arkanum;User Id=<user>;Password=<password>;Encrypt=True;TrustServerCertificate=True;' \
  ARKANUM_RESTORE_KEY_FILE='/path/to/master-key.txt' \
  installers/linux/install-arkanum.sh
```

If validation fails, restore mode reports:

```text
The provided Recovery Key does not match this database.
```

## Credential reset notifications

Vault credential rows now expose a `Reset notification` date field. Setting or changing the date clears prior sent status.

A reminder service can send due reminder digest emails to eligible vault members while excluding global administrators. Reminder email bodies do not include secret values.

## CSV export

Vault pages now include:

```text
Export vault CSV
```

Settings includes:

```text
Export all vaults
```

Exports are ZIP packages containing:

```text
manifest.json
credentials.csv.aes
```

The CSV payload is encrypted using the export passphrase with AES-256-CBC and PBKDF2-SHA256. Audit logs record that an export occurred without logging secret values.

PDF reports remain deferred for later user feedback.
